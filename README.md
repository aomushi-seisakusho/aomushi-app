# あおむし製作所｜アプリの箱（公開）

スマホのホーム画面から開く会社の一元画面。GitHub Pages で配る。

**この箱は公開。だから会社の数字は1つも入っていない。**
数字は非公開の金庫（`aomushi-data`）にあり、アプリは端末に保存した鍵（トークン）で読む。
鍵はブラウザの中だけに残り、どこにも送信されない。

## 画面

| タブ | 中身 |
|---|---|
| 工場 | 社屋の絵（state.json駆動）・今日の要件・会社の宿題・社員名簿・タイムライン |
| **決裁** | **会社の唯一の窓口。**今日やること（1〜3件）／ネタを放る／決裁箱／出せる弾／さっき片づけた分／係からの返事 |
| 台帳 | 全投稿を views順・いいね率順・新しい順で。型は手分類のみ表示 |

**社内便は廃止した（v17）。** タブも、係あてに手紙を出す口そのものも消した。
窓口が2つあると、要件がどちらに出たか探すことになる。
残したのは「係からの返事」だけ＝**写せなかったときの理由がそこに出る**ので、消すと行き止まりになる。

## 決裁箱（第6期）

Macの毎朝の点呼（`tenko.py`）が積んだ要件が、1つの列に並ぶ。

| 札 | 中身 | 押すと |
|---|---|---|
| 要件 | 記録係の数字／会社のリズム督促／偵察係の熱／執筆係の詰まり | 了解・却下（`inbox/*-yoken-*.json`） |
| 取材 | 採掘係の質問（本文ごと） | 答え→ N-在庫が1本増える |
| 決裁 | 初校の下書き（本文ごと） | 校了・差し戻し |
| 在庫の空欄 | 未使用N-の「誰が／そのままの言葉／僕の感情」 | 埋める→ 3欄そろえば執筆係の弾になる |

- **押した札は、その瞬間に箱から消える。** 足取りは「さっき片づけた分」に残る（黙って消さない）
- 金庫に置けなかった札は箱に戻り、書いた言葉も欄に戻る（行き止まりを作らない）
- タブの数字＝未処理の件数。0なら数字は出ない
- ネタを1行放ると `capture.add` でN-在庫が1本増える（細部は空のまま。あとで空欄を埋める）

## 取材（第5期）

質問は金庫の `state/state.json` の `shuzai` に入っている（本文・隣のE-・狙い・どのN-になったか）。
答えを書いて置くと `inbox/` に `kind:"shuzai"` の札が1枚できる。Macがそれを読んで
`vault/episodes.md` に **N- を1本積む**。アプリ側は在庫を書き換えない。

- 札は決裁と同じ3つ。ただし最後は「係が読んだ」ではなく **「在庫に入った」**（`N-002` まで出す）
- 書きかけは質問ごとに端末に残る。置けなかったときも消えない
- Macが取り込む前なら取り消せる（答えは欄に戻る）

## 金庫に置くもの（第6期）

決裁箱で押した札だけが、金庫の `inbox/` に1件1ファイルのJSONで置かれる
（GitHub Contents API の PUT）。Macが次に `haitatsu.py` を回したとき、機械がそれを写す。

| kind | 中身 | 写す先 |
|---|---|---|
| `kessai` | 下書きの校了・差し戻し | `drafts/<原稿>.txt.pass` / `.reject` |
| `shuzai` | 取材の答え | `vault/episodes.md` に N- が1本増える |
| `ume` | 在庫の空欄1つ | `vault/episodes.md` のその欄（**一字も直さない**） |
| `neta` | 放った1行 | `capture.add` で N- が1本増える |
| `yoken` | 要件の了解・却下 | `vault/yoken.json` |

- 鍵（トークン）は **Contents: Read and write** が要る。読み取りだけの鍵だと置けない
- 置いた直後は state.json にまだ載らないので、端末の控えで「送った（未読）」と出しておく
- 書きかけは端末に残る。アプリが裏に回っても、通信に失敗しても消えない

## 決めごと

- **投稿ボタンは作らない。** Threadsへの送信も返信も人間の手で（憲法4条）。
  この箱から置けるのは金庫の `inbox/` までで、Threads APIは一切叩かない
- **型は人が読んで決めたものだけ出す。** 機械の自動判定は画面に出さない
- いいね数だけの順位は作らない。判定は views と いいね率の2軸（憲法2条）
