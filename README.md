# あおむし製作所｜アプリの箱（公開）

スマホのホーム画面から開く会社の一元画面。GitHub Pages で配る。

**この箱は公開。だから会社の数字は1つも入っていない。**
数字は非公開の金庫（`aomushi-data`）にあり、アプリは端末に保存した鍵（トークン）で読む。
鍵はブラウザの中だけに残り、どこにも送信されない。

## 画面

| タブ | 中身 |
|---|---|
| 工場 | 社屋の絵（state.json駆動）・決裁デスク・社員名簿・タイムライン |
| 社内便 | 係あてに手紙を出す（第2期）／係からの返事／編集長が送った手紙 |
| 決裁 | **取材（採掘係の質問に本文ごと出て、その場で答える）**／下書きの校了・差し戻し |
| 台帳 | 全投稿を views順・いいね率順・新しい順で。型は手分類のみ表示 |

## 取材（第5期）

質問は金庫の `state/state.json` の `shuzai` に入っている（本文・隣のE-・狙い・どのN-になったか）。
答えを書いて置くと `inbox/` に `kind:"shuzai"` の手紙が1通できる。Macがそれを読んで
`vault/episodes.md` に **N- を1本積む**。アプリ側は在庫を書き換えない。

- 札は決裁と同じ3つ。ただし最後は「係が読んだ」ではなく **「在庫に入った」**（`N-002` まで出す）
- 書きかけは質問ごとに端末に残る。置けなかったときも消えない
- Macが取り込む前なら取り消せる（答えは欄に戻る）

## ファイル

| | |
|---|---|
| `index.html` / `style.css` / `app.js` | 画面本体 |
| `config.js` | つなぎ先（GitHubのユーザー名と金庫の名前） |

| `manifest.webmanifest` / `icons/` | ホーム画面に置くための看板 |

## 社内便の送信（第2期）

宛先・件名・本文を書いて「金庫に入れる」と、金庫の `inbox/` に1通1ファイルの JSON を置く
（GitHub Contents API の PUT）。Macが次に `state.py` を回したとき、係がそれを読む。

- 鍵（トークン）は **Contents: Read and write** が要る。読み取りだけの鍵だと置けない
- 置いた直後は state.json にまだ載らないので、黄色い線つきで「金庫に置いた」と出しておく
- 書きかけは端末に残る。アプリが裏に回っても消えない

## 決めごと

- **投稿ボタンは作らない。** Threadsへの送信も返信も人間の手で（憲法4条）。
  社内便で置けるのは `inbox/` の手紙だけ。Threads APIはこの箱から一切叩かない
- **型は人が読んで決めたものだけ出す。** 機械の自動判定は画面に出さない
- いいね数だけの順位は作らない。判定は views と いいね率の2軸（憲法2条）
